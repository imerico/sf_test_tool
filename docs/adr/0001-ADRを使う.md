# 0001. 設計上の決定を ADR として記録する

- 日付: 2026-11-27
- 状態: 承認
- 関連 Issue: #1

## 背景

このリポジトリは imerico と e-tkis の 2 アカウントで開発する。これまで設計上の判断（Neutralinojs で exe にする、データを localStorage に保存する、など）は、コミットメッセージや口頭でしか残っておらず、後から「なぜこうなっているか」を追えない。

## 決定

設計上の判断は ADR（Architecture Decision Record）として `docs/adr/` に記録する。

- 形式は Nygard 形式（状態／背景／決定／結果）とし、日本語で書く。ひな形は `docs/adr/template.md`。
- ファイル名は `NNNN-タイトル.md`（4 桁の連番）。番号は一度付けたら変えない。
- 番号の重複とファイル名の形式は CI（`adr-number` チェック）で確認する。
- 判断が必要な課題は、Issue フォーム「設計の検討（ADR 候補）」で起票し、ADR の「関連 Issue」欄に番号を書く（任意）。
- ADR を書くかどうかは PR テンプレートのチェック項目で確認する。書くことは必須にしない。
- 決定を取り消す・変えるときは、ファイルを消さず、状態を「廃止」または「置き換え（ADR-NNNN）」に変え、新しい ADR を追加する。

## 結果

- 設計の理由が、コードと同じ場所に履歴として残る。
- ADR を書く手間が増える。必須にはしないため、書き忘れは PR のレビュー時に気づく運用になる。
- 2 人が同時に同じ番号を付けた場合、後からマージする側が `git rebase main` して番号を振り直す必要がある。
